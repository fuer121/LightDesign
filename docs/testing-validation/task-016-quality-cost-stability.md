## 8. 成本 / 稳定性判断
- 成本：本轮产生至少 2 次真实外部生成调用；由于 API 响应未返回计费明细，不能给出精确单次成本。
- 稳定性：应用路由已从错误的站点 HTML 响应修正为真实 API JSON 链路，并完成 1 次真实商品图成功返回。
- 风险：原始大图仍建议在产品层增加压缩或尺寸提示，避免大 data URL 增加传输耗时和失败概率。

## 9. 是否建议进入生产级验证
- 结论：**暂不建议直接进入生产级验证，建议进入扩样本验证**。
- 原因：
  - 当前只有 1 张真实商品图，无法覆盖不同类目、材质、背景复杂度。
  - 需要至少 3-5 张代表性商品图，才能判断主体保真、文字稳定性、失败率和耗时分布。
  - 对话式调整链路已同步修复底层请求，但尚未用真实远程图做单独验收。

## 10. 下一轮建议
1. 继续补充 2-4 张真实商品图，覆盖不同商品类型和背景复杂度。
2. 每张图只跑 1 次应用 `/api/generate`，记录是否返回 `remote-url`、耗时、主体保真和文字可读性。
3. 选 1 张生成结果再跑 1 次 `/api/adjust`，验证“对话式调整”真实远程图链路。
4. PR 前确认不纳入根目录误生成的 `node_modules/` 和根 `package.json`。
